01 / 10Introduction
Amortized Analysis
Two Pointers  ·  Sliding Window

Some algorithms look slow step-by-step but are blazing fast overall. Amortized analysis reveals the truth by studying the total cost across all operations — not just the worst single one.

Two Pointers

Two indices moving through an array in one direction each. Solves subarray sum & pair problems in O(n).

Sliding Window

A fixed-size window sliding right, maintaining the minimum with a deque in O(n) instead of O(nk).

Core idea: A pointer that moves at most n total steps across all iterations can never cost more than O(n) — regardless of how unevenly those steps are distributed.
02 / 10Core Concept
What is Amortized Analysis?
Analogy: You pay €30 for groceries most weeks, but once a month you stock up and spend €150. The amortized cost per week is €45 — far more accurate than the €150 peak.
The idea: Instead of bounding each operation's worst case, bound the total cost of all operations together, then divide by the number of operations.
When it matters: Operations whose cost varies — most are cheap O(1), a few are expensive O(n) — but the expensive ones are rare enough to keep the total budget under O(n).
The trick: Find a potential or budget argument. E.g. "each element can only be added and removed once, so even if one step removes 10 elements, those 10 will never be removed again."

❌ Naïve (wrong) bound

Each step removes up to n items → n steps × O(n) = O(n²).
This is too pessimistic.

✅ Amortized (correct) bound

Total removals across all steps ≤ n (each item removed once) → O(n) total.

03 / 10Two Pointers
Why use it & when does it apply?
Why it works
By keeping two indices that each only move forward, we avoid re-scanning elements we've already processed. The total number of index moves is bounded by 2n — amortized O(1) per element.
Use two pointers when…

Sorted array + pair/sum

Find two elements summing to a target. Left moves right, right moves left.

Positive integers + subarray

Find subarray with sum = x. Both pointers move right only.

Remove duplicates

In-place dedup on sorted array using a slow + fast pointer pair.

Do NOT use when…
Array has negative numbers and you need a subarray sum (use prefix sums instead).
You need all pairs, not just one — two pointers finds one in O(n), not all O(n²) pairs.
Data is unsorted and sorting it first is not allowed (e.g. must preserve order for a non-sum query).

06 / 10Sliding Window
Why use it & when does it apply?
Problem: You have an array and a window of fixed size k. As the window slides right one step at a time, you need the minimum (or maximum) inside the window at every position. Naïve: scan window each step = O(nk). With a deque: O(n).
Use sliding window minimum when…

Fixed window stats

Min/max over every window of size k. Classic sliding window minimum.

Moving average

Running sum / average over a fixed-length period (e.g. 7-day stock avg).

Range min queries

Offline queries where windows are traversed left-to-right — deque gives O(1) per query.

How the deque works
The deque stores indices in increasing order of their values. Front = smallest = window minimum.
When a new element arrives, pop from the back while back value ≥ new value (they're shadowed forever).
When the front element falls outside the window, pop from the front. Then front = new minimum.

08 / 10Amortized Proof
Why both methods are O(n)
The budget argument
Give each element a token budget. For two pointers: 1 token for L moving past, 1 for R moving past = 2n tokens total. For sliding window: 1 token for entering deque, 1 for leaving = 2n tokens total. Once a token is spent, it's gone. The algorithm stops when all tokens are spent → O(n) total work.
Right pointer budget (Two Pointers demo — n=8)
For sliding window
Each element enters deque exactly once.
Appended to back when window reaches it.
Each element leaves deque at most once.
Popped from back (shadowed) or front (out of window).
Worst single step: O(n)  ·  Amortized per element: O(1)  ·  Total: O(n)

10 / 10Summary
Key takeaways

🔁 Amortized thinking

  • Count total operations, not per-step worst case
  • Use a "token budget" argument
  • Each element's lifecycle (in/out once) is the key

↔ Two Pointers

  • Subarray sum (positive ints) → O(n)
  • 2SUM on sorted array → O(n log n)
  • 3SUM → O(n²)
  • Both pointers only move forward

🪟 Sliding Window

  • Window min/max → O(n)
  • Deque: ascending order, front = min
  • Back pop: new element shadows old ones
  • Front pop: element left window
